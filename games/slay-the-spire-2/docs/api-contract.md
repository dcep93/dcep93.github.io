# API contract and evidence

Inspected 2026-11-25 against local STS2 **v0.114.0**, commit **a7b9a9c0**, Steam build **26909018**, public-beta, Apple Silicon. Game assembly targets .NET 9; installed game runtime is 9.0.7. Draft build SDK: 9.0.321. IL inspection: ILSpyCmd 9.1.0.7988. The initial API checks were offline and did not control the running game. Subsequent save-recovery evidence is documented below.

## Loader

Inspected `ModManager`, `ModManifest`, and `ModInitializerAttribute` in the installed assembly. The loader recursively reads `.json` manifests below the executable's `mods/` directory. It resolves the DLL by mod ID and invokes the method named by `[ModInitializer]`. Our initializer is public/static/no-argument. Settings are `settings.json.txt` to avoid manifest discovery. No `.pck` is needed because all art/shaders are already provided by the installed game.

## Save migration and cloud sync

First-use logs on 2026-11-25 showed `ModManager` copying unmodded saves into `modded/`, followed by cloud sync deleting the copied progress, current run, preferences, and history because those paths did not exist remotely. The game then created fresh modded progress. The original unmodded files remained intact. The same log confirmed successful initialization of spire420 and all six MapColors hooks; this save loss occurred in the game's migration/synchronization path.

Read-only inspection of `SaveManager`, `CloudSaveStore`, and `SteamRemoteSaveStore` confirmed:

- Cloud-to-local synchronization treats remote absence as deletion of the local file and its backup. A newer local timestamp alone does not protect a restored file.
- Local-only run history is retained when the local and cloud progress files have the same readable `unique_id`; absent or mismatched IDs permit its removal.
- Steam save filenames use paths such as `modded/profile1/saves/progress.save`, without the local Steam account directory prefix. Writes use `SteamRemoteStorage.FileWrite`, with batch begin/end support.
- `ShouldOverwriteCloudWithLocal` selects upload when cloud sync is disabled, or when local profile data exists and the entire cloud backend has no files. An empty modded profile does not imply that the entire backend is empty.

Recovery was performed with the game closed, after backing up local saves and Steam's cache. The original profile was copied into the separate modded profile; a temporary helper outside this repository restored its non-backup files through Steam's save API and verified every file by read-back. Vanilla files were checked for byte equality before and after. No recovery logic or save-writing hooks were added to spire420.

## Hooks and state

| Exact hook | Purpose |
| --- | --- |
| `NNormalMapPoint.RefreshColorInstantly(): void` postfix | Reapply room fill color after the game resets its shader. |
| `NBossMapPoint.RefreshColorInstantly(): void` postfix | Recolor the existing boss shader or placeholder art. |
| `NMapLegendItem._Ready(): void` postfix | Match the six legend icons to the palette. |
| `NAncientMapPoint.get_TraveledColor(): Color` postfix | Ancient's reachable/visited tint through the game's own animation target. |
| `NAncientMapPoint.get_UntravelableColor(): Color` postfix | Ancient's unavailable tint and reduced alpha. |
| `NAncientMapPoint.get_HoveredColor(): Color` postfix | Same Ancient hue on hover; no delayed retint timers. |

The contract checker reflects each exact declared method with its return type and empty parameter list. Private fields are verified with their exact types: boss `_usesSpine: bool`, `_material: ShaderMaterial`, `_animController: MegaSprite`; legend `_pointType: MapPointType`.

`MapPointType` distinguishes `Unknown` from `Unassigned`; we do not infer hidden outcomes or tint arbitrary custom types. Normal nodes call refresh after `%Icon` initialization in `_Ready`. The refresh updates `SelfModulate`, outline modulation, and `map_color`; its postfix changes only the fill parameter on a private material. Hover/selection animations alter icon alpha/scale and outline modulation, not this fill parameter, so no frame loop or timers are needed.

Normal icon scene: `%Icon` is `IconContainer/Icon`, `%Outline` is `IconContainer/Icon/Outline`. Native shader exposes `initial_color` and `map_color`. Native dark artwork remains the contrast boundary. The draft reuses existing outlines instead of replacing the shader or adding extra artwork. The legend uses the same atlas artwork without a material; it receives the game's normal icon shader and the verified `initial_color` constant. Neither labels nor hover behavior are altered.

Boss Spine art uses `map_color` plus `black_layer_color`. Clone its material, assign it through `MegaSprite.SetNormalMaterial`, and update the boss's cached field so future refreshes target the clone. Keep `black_layer_color` unchanged because it communicates visited/unavailable state. Placeholder bosses have `%PlaceholderImage`; its hue is changed after native refresh while preserving base alpha and reducing unavailable opacity.

Ancient scenes use `Icon` and `Icon/Outline`, with native getter-driven color tweens. Change only the three getter results, keeping native alpha and reducing unavailable alpha to 55%. Native outlines, scale tweens, inputs, and controller selection remain game-owned.

## MapControls input contract (draft 0.2.0)

| Exact declared hook | Patch and checked contract |
| --- | --- |
| `NMapScreen.ProcessMouseEvent(InputEvent): void` (private instance) | Transpiler; exactly **one** `InputEventMouseButton.get_ButtonIndex(): MouseButton` call. |
| `NMapScreen.ProcessMouseDrawingEvent(InputEvent): void` (private instance) | Transpiler; exactly **two** button getter calls. Prefix skips primary-press drawing starts over this screen's map points. |
| `NMouseHeldMapDrawingInput.ProcessMouseDrawingEvent(InputEvent): void` (private instance) | Transpiler; exactly **one** button getter call, mapping primary release to the native Right listener. |

All three transpilers insert the pure static `MapControlsApi.Swap(MouseButton)` immediately after each getter call: Left becomes Right, Right becomes Left, every other value is unchanged. Original instruction objects, operands, labels, and exception metadata are retained. Original input events are neither replaced nor mutated, so pan/wheel processing, node input and other event consumers see the native event. There are no patches on `NButton`, node methods, global input, drawing motion handlers, or controllers.

All three exact declared handler signatures, the native `get_ListeningButton(): MouseButton` signature, and all three getter counts are validated before any patches are installed. The transpilers recheck the actual instruction stream supplied by Harmony, rejecting changed counts instead of guessing. The owner is `dcep93.spire420.MapControls`; a patch-installation failure rolls back only that owner and lets ModuleHost continue other modules. These checks catch signature/site changes, not every possible semantic game update or conflict with another mod.

Inspected native `NMapScreen._GuiInput` routes background events to `ProcessMouseEvent` and then the unchanged `ProcessScrollEvent`. Native drawing starts only when input is enabled, the act animation is not running, and there is no existing drawing input. Native scrolling keeps `CanScroll`, animation cancellation, drag positions, motion handling and bounds. `NMouseHeldMapDrawingInput` ends drawing when its event button read matches its listening button on release. Translating that read maps primary release to native Right while preserving Middle for erasing and leaves the original event untouched. The tiny `ListeningButton` getter itself stays native (Right for drawing, Middle for erasing); avoiding a getter detour removes any dependence on whether the JIT inlines it. The drawing cleanup/networking lifecycle stays native. Toolbar drawing uses the original separate lifecycle.

**Node bubbling conflict and scoped guard:** `NMapPoint` inherits `NButton`/`NClickableControl`. Native `NClickableControl._GuiInput` emits mouse signals and handles primary presses/releases but does not call `AcceptEvent`; normal, boss and ancient scene roots set `mouse_filter = 1` (Pass). A naive left/right swap would therefore start background drawing on a room click, and `NMapPoint.OnRelease` requires drawing mode None before selecting a room. The drawing-handler prefix checks physical Left pressed only and walks the deepest hovered control's parents to identify a map point belonging to this exact map screen. It skips that background drawing start, leaving the node's original click handling intact. [Godot's hovered-control contract](https://docs.godotengine.org/en/stable/classes/class_viewport.html#class-viewport-method-gui-get-hovered-control) specifies the deepest hovered control; the ancestor walk covers nested icon controls. A failed hit inspection refuses to start the stroke and reports once. Background starts and strokes already crossing nodes retain native drawing behavior; other buttons and events pass through the guard.

`MapControls` is enabled by default and shipped as `true`. Existing settings that omit it enable it without rewriting the user's file; an explicit `false` prevents initialization. Autoplay remains inert. The input change affects local map annotation/scrolling only and leaves the manifest's `affects_gameplay: false` unchanged.

Native gesture testing remains pending. The README checklist covers primary draw/release, secondary scroll/release, point selection, pan/wheel, middle erase, toolbar, controller, and the disable toggle. Offline reflection and IL checks do not establish that Harmony installed correctly in a running game or that trackpad gestures feel correct.

## Failure and ownership rules

MapColors validates all six hook signatures before patching. Use the owner `dcep93.spire420.MapColors`; rollback that owner's patches if initialization fails. Per-point scene mismatches log once per distinct error and keep unsupported visuals vanilla. Exact runtime types only: custom subclasses are not modified. A per-owner weak table holds cloned materials so nodes cannot recolor each other. No root-level tint, gameplay callbacks, or per-frame work.

API signature checks cannot prove shader output or Harmony runtime behavior. They catch missing/renamed/type-changed hooks; game updates can preserve signatures while changing meaning. Offline tests and a successful build are prerequisites, not in-game acceptance. The user's visual testing remains pending, including f.lux warmth, boss artwork, availability cues, and co-op display.

Independent review also checked the native texture/shader mask: Shop and Rest have relatively small recolorable regions, so their accents may need strengthening after the user's f.lux test. Retaining the native mask is intentional for this first draft; it preserves the dark artwork. The legend now validates its material-free scene and both shader uniforms before assignment, and refuses unexpected subsequent material replacement.

## BattleStats contract (draft 0.4.1)

BattleStats owns `dcep93.spire420.BattleStats` and defaults to enabled, including existing settings without its key. Initialization validates dependencies before installing two postfixes: declared public `NCombatRoom._Ready(): void` and `RunHistorySaveManager.SaveHistory(RunHistory): void`. The managed checker generates their real Harmony replacements, verifies the exact owner/target/postfix set, and removes them in `finally`, without invoking patched game methods or creating native objects. Failure rolls back this owner and unsubscribes its events; other modules continue.

The service subscribes `CombatManager.CombatSetUp: Action<CombatState>` and `CombatWon` / `CombatEnded: Action<CombatRoom>`. Setup fires before `AfterRoomEntered` and before start-of-combat damage. It captures `LocalContext.GetMe(ICombatState)`, the exact combat state, the current `MapPointHistoryEntry`, and that player's `PlayerMapPointHistoryEntry.DamageTaken` reference. A single-room fight uses the native counter with baseline zero, preserving ordinary resumed-combat totals. Multi-room live fights subtract the setup counter. Healing and HP are never used to infer damage. Samples are integer damage counts; means and medians use the individual samples, include zeroes, pool characters/difficulties for the exact encounter ID within the current native game mode and exclude the active battle key. σ is the displayed mean symbol, not standard deviation.

The battle key uses read-only `RunManager._startTime: long`, `IRunState.Rng.StringSeed`, local player ID, actual zero-based act/history-entry/room list positions, and full encounter ID. Setup verifies the last history room matches the encounter. Completion requires the captured state's identity, the same profile, run start, local player and history entry. Its completion gate rejects abandonment, replay, invalid counters and repeated callbacks. Only combat completion events and matching saved loss history can commit; scene exit/reset does not. Replay detection uses `RunManager.NetService.Type == NetGameType.Replay`; no tests-only game API is called.

A loss can reach `RunManager.OnEnded(false)` and save its history before the pending loss safe point emits `CombatEnded`. The `SaveHistory` postfix runs after the native method succeeds and passes its argument through `JsonSerializationUtility.ToJson`, the game's own history serializer. Import uses identical keys, so loss fallback and later completion upsert the same battle. A matching non-abandoned death can also commit its captured nested-combat baseline because raw multi-room history is ambiguous. Earlier current-run points are imported from a read-only `RunHistory` projection with `WasAbandoned = true`, forcing the current final point to be excluded. This projection explicitly carries `GameMode = state.RunState.GameMode` and never calls native save or history-creation APIs.

Profile identity is `ProjectSettings.GlobalizePath(UserDataPathProvider.GetProfileScopedBasePath(SaveManager.Instance.CurrentProfileId))` plus `SaveManager.Instance.Progress.UniqueId`. Initialization waits for `IsProfileInitialized` and modded context; the one-time scan waits for `LocalContext.NetId`. Switching profiles discards the live context and loads the matching database. Storage is `ProjectSettings.GlobalizePath("user://spire420/battle-stats")`, outside the account/profile/cloud tree and outside the installed mod. It is local and not Steam-synced. Native `saves/history/*.run` files are read-only inputs. The importer requires exactly one combat room with an ENCOUNTER ID, an unambiguous player and a nonnegative integer counter. Earlier points count; the final point needs a win or matching encounter death and must not be abandoned. Corrupt files are isolated. Atomic database writes preserve a backup and refuse to overwrite unreadable/unsupported data.

Every combat scene receives a native `Label` and `Godot.Timer` directly under `NCombatRoom` after `_Ready`, initially hidden, including VisualOnly scenes that can later transition to ActiveCombat without another `_Ready`. The 0.4.0 label is right-aligned immediately below the actual native `NRun/GlobalUi/DebugInfo` build/seed/modded information, using visible label bounds transformed into the room's coordinates. It uses larger outlined white text, `MouseFilter.Ignore`, and no panel or opaque background. Placement is recalculated on refresh to follow resizing. A top-right fallback logs once if the native info cannot be resolved. `SystemFont.FontNames` requests Hiragino Sans, Noto Sans CJK JP, Microsoft YaHei and sans-serif fallback for 今/中/Σ. No custom Godot Node subclass or source generator is used. The label remains outside `SceneContainer` to avoid combat camera scaling/offsets.

Mode-aware storage preserves the original mode-free BattleKey. Legacy schema1 samples start with unknown mode; read-only native history reimport replaces the same keys with recovered modes. Missing `game_mode` follows native `RunHistory.GameMode`'s Standard initializer; invalid explicit values are not silently assigned Standard. Unknown-mode legacy records never enter known-mode summaries. Migration and backups happen in the new runtime after user restart; the installer does not write stats databases.

The `Σ` suffix uses native `AttackIntent.GetTotalDamage(targets, owner)`: `GetSingleDamage` applies native damage hooks for the local player, and `MultiAttackIntent` multiplies by its dynamic or fixed `Repeats`. Sum current living enemy attack intents, not base model damage or HP differences. Nonattack intents contribute zero; hidden/unknown/unavailable intents must not imply a known total. Only visible native intent entries matching the current model identity and not frozen by `NIntent.SetFrozen` are eligible. Native intent objects freeze displayed values while an enemy starts acting; the overlay reports `Σ?` through that transition rather than recomputing a conflicting total. This is a preview before player block, not simulation of future enemy actions.
The 0.25-second timer displays only with ActiveCombat mode, in-progress combat, and `ActiveScreenContext.Instance.IsCurrent(room)` (covering map, overlays, gameover and event-room transitions). Validated private `NCombatRoom._visuals: ICombatRoomVisuals` identifies the exact `CombatRoom.CombatState`, preventing another scene from displaying the current fight's data. Aggregates are cached by store version, profile, encounter, game mode and battle key. Active-screen changes also refresh immediately through `ActiveScreenContext.Updated`, including while the scene tree is paused. Scene exit disconnects that subscription and stops/disconnects the timer and removes the per-view weak-table registration; native children are freed with the scene. Runtime errors log once per operation and do not propagate into gameplay.

Managed checks cover native property/method/event/private-field and enum signatures, exact patch installation/removal, stale-state/profile completion, deduplication, abandonment/replay rejection, damage baselines, zero damage and visibility combinations, alongside the pure data/persistence checks. Native text rendering, fallback glyph coverage, position, event transitions, map/overlay hiding, loss/reload behavior and user input remain manual acceptance items at the next user-controlled restart; see the README checklist.
